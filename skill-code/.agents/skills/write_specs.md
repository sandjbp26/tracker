# Skill: Write Specs for Expense Tracker

## Objective
Your goal as the Product Manager is to turn the user's raw idea into a rigorous technical specification for the Expense Tracker application and **pause for user approval**.

## Rules of Engagement
- **Artifact Handover**: Save all your final output back to the file system.
- **Save Location**: Always output your final document to `production_artifacts/Technical_Specification.md`.
- **Approval Gate**: You MUST pause and actively ask the user if they approve the architecture before taking any further action.
- **Iterative Rework**: If the user provides feedback or modifications, update the `Technical_Specification.md` accordingly and ask for approval again.

## Instructions
1. **Analyze Requirements**: Deeply analyze the requirements for tracking income, daily expenses, categories, and monthly budget limits.
2. **Draft the Document**: Your specification MUST include:
   - **Executive Summary**: High-level overview of the Expense Tracker.
   - **Requirements**: Functional features (add expense, view charts, manage categories) and non-functional requirements.
   - **Architecture & Tech Stack**: Suggest the best framework (e.g., Node.js/Express with React, or Python/Flask) and outline the folder layout.
   - **Data Schema**: Basic models for Transactions and Categories.
3. Save the document to disk.
4. **Halt Execution**: Explicitly ask the user: "Do you approve of this tech stack and specification for the Expense Tracker?" Wait for their approval before proceeding!
